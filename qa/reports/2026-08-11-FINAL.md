### Root Causes Addressed

1. **Incomplete Invariant Chains** (48 bugs)
   - Problem: `!value.to_s.empty?` without `pattern: '[^ \t\n\r]'` allows whitespace-only
   - Fix: Add pattern validation + invariant
   - Framework: Affects all string identifiers across 12 domains

2. **No Validation at All** (12 bugs)
   - Problem: VOs with zero constraints
   - Fix: Add pattern + invariant for strings, positive/non-negative for integers
   - Examples: Flag, CatalogueRef, Money VO instances

3. **Type Mismatches** (2 bugs)
   - Problem: DailyFee using Float instead of Integer for monetary amounts
   - Fix: Changed to Integer with cents semantics
   - Critical: Violates domain invariant

4. **Design Conflicts** (3 bugs)
   - Problem: DailyLimit default (0) violates invariant (positive)
   - Problem: SafeDepositBox missing Create command
   - Fix: Update default value + add command

## Framework Improvement Recommendations

From FRAMEWORK_NICE_TO_HAVE.md, top 3 preventables:

1. **Pattern Validation Helpers** (would prevent ~30 bugs)
   ```ruby
   # Instead of: pattern: '[^ \t\n\r]' + invariant("...") { !value.to_s.empty? }
   # Use: no_whitespace_only: true
   attribute :value, String, no_whitespace_only: true
   ```

2. **Default Value Validation at DSL Time** (would prevent ~3 bugs)
   - Linter rule: "default value violates invariant"
   - Caught at domain load time, not runtime

3. **Closed-Set Support in Value Objects** (would prevent ~5 bugs)
   - Currently only works at aggregate level
   - Would help: Flag, QuestionSource, etc.

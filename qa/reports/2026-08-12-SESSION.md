## Framework Design Observations

### Auto-Assignment Feature (Undocumented Behavior)
- Creating commands auto-assign all declared attributes to the aggregate
- Explicit then_set is OPTIONAL but RECOMMENDED for clarity
- CardPayment.Authorize relies on this (no then_set for authorisation, but it gets set)
- CreatePizza was fixed with explicit then_sets, but auto-assignment would have worked

**Recommendation:** Consider documenting this auto-assignment behavior or making it explicit in all creating commands for clarity.

### Pattern Validation Timing
- Patterns validated during normalize_args (early)
- Given() predicates validated afterward
- Means patterns catch errors that business logic can't test
- May want to add test variants that skip pattern validation for business logic testing

## Next Session Recommendations

Rather than line-by-line code inspection, consider:

1. **State Machine Exhaustion** - Run all possible command sequences for each aggregate
2. **Cross-Domain Scenarios** - Test reactions, sagas, complex workflows
3. **Edge Cases** - Zero balances, empty lists, concurrent operations
4. **Evolution Testing** - Test era/lineage changes with real data
5. **Query Fuzzing** - Generate random queries to find edge cases

These approaches more likely to uncover hidden bugs than code inspection.
